# Weekly pearls infographic

Renders the weekly "six pearls" recap for the Telegram channel **@mrcp_gafar**
as a 1080×1350 PNG, in a dark and a light theme.

Text is rendered as real HTML text and screenshotted — never generated by an
image model. Every threshold, dose and drug name is pixel-exact by construction.

## Build

```bash
python3 build.py                       # writes weekly_dark.html + weekly_light.html
node shoot.mjs weekly_dark weekly_light # renders 2160×2700 PNGs (2× of 1080×1350)
```

`shoot.mjs` exits non-zero if any layout fails to fit. Never publish output from
a failed run.

Requires: Chromium (`/opt/pw-browsers/chromium-*/chrome-linux/chrome`), Node 22,
Python 3 with `qrcode`. Fonts are vendored in `fonts/` so rendering is
reproducible without network access.

## What to edit

Everything intended for tweaking is the `CONFIG` block at the top of `build.py`:
brand handle/URL/author, specialty, `WEEK_START`, and the per-theme accent lists.
Colours live as tokens in `weekly.css`; `[data-theme="light"]` swaps them, so a
theme change is one value, not a fork.

`content.js` holds the six pearls. This is the seam the pipeline will feed.

## Week numbering

ISO-8601, derived from `WEEK_START` — week 1 is the week containing the first
Thursday, weeks run Monday–Sunday. Same rule Python, Postgres and n8n use, so
the automation and any manual check always agree, including at year boundaries.

## Four things that will bite you

These were all found the hard way; the fixes are in the code and must stay.

1. **Fit must wait for `document.fonts.ready`.** Measuring against fallback
   metrics reports a comfortable fit; the real webfont then swaps in and pushes
   the footer off the canvas. Silent, and the page looks fine until you scroll.
2. **Decorative layers are excluded from the fit** via `[data-decor]`. The plate
   and watermark bleed off-canvas by design; without the exclusion the fitter
   shrinks body text to its floor trying to drag artwork back on screen.
3. **Anything in the flex column that must keep its height needs pinning.** The
   ECG is `flex: 0 0 78px`; without it the fitter squeezed it to zero height
   while growing the cards.
4. **`body.scrollHeight` cannot detect overflow here** — body has a fixed height
   so it clamps to 1350 while content hangs off the bottom. Measure real element
   rects instead.

The fit grows as well as shrinks, so short weeks fill the canvas and long weeks
stay inside it. If it still cannot fit, the build fails rather than clipping.

## QR code

Generated as vector from `BRAND["url"]`, so it stays sharp and recolours with the
theme. Rendered at 116px — below roughly 100px it is too small to scan off a
phone screen after Telegram's compression. Verify after any change to the footer:

```python
import cv2, numpy as np; from PIL import Image
im = Image.open("out/week34-dark.png").convert("RGB")
arr = np.array(im.crop((60, im.height-500, 760, im.height)))[:, :, ::-1].copy()
print(cv2.QRCodeDetector().detectAndDecode(arr)[0])
```

## Not built yet

The pipeline around the template:

- **Select** last week's rows from the `Cardio V3` Notion database —
  `Post date` within the week AND `Status = Posted` (`Posted` is only set after
  the 22:00 answer fires, so it means the full daily cycle completed).
- **Compress** each pearl to ≤90 characters for a card. Gate it: every number,
  unit and drug name in the card must appear byte-identical in the source pearl.
  Reuse the token extractor from `mrcp-telegram-drip/scripts/verify_numbers.py`.
  If a pearl cannot compress without losing its threshold, drop it — never
  paraphrase a number.
- **Review gate** before publishing, mirroring the drip's "Status is never Ready"
  refusal: send to a private chat with Publish / Regenerate / Cancel, and only
  then post to the channel.
- **Archive** a weekly digest row for idempotency (never post the same ISO week
  twice) and skip silently if fewer than three rows qualify.
